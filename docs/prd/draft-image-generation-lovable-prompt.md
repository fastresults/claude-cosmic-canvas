# Draft → Image Generation Workflow — Portable Lovable Prompt

> **How to use this document**
> Paste this entire file as the initial prompt into a new Lovable project (or hand it to an AI agent in an existing one). It reproduces our shipped `Draft → Generate Image → Attach to Card` workflow end‑to‑end. It is architecture, data contracts, edge‑function shapes, LLM system prompts, and mobile‑first UI states — **zero visual styling opinions**. The target app owns its own aesthetic.

---

## 0. Source of truth (this repo)

The target app should mirror the shape of these working artifacts. When in doubt, this is the reference implementation:

## 1. Overview & user story

**Story.** *As a creator, from any draft card in the app I can attach a cover, social, or inline image — generated by AI, uploaded from device, or reused from my library — in ≤3 taps, on a phone, without leaving the draft.*

**Non‑negotiables.**
- AI‑first: default action opens a Generate flow with 3 grounded concepts already loading.
- Mobile‑first: the sheet is a bottom sheet on `<640px`; primary CTAs live in the thumb‑zone.
- Streamed: partial frames render as they arrive, blurred, and sharpen on completion.
- Polymorphic: one image subsystem serves every draft type (blog, email, PR, post, …).

---

## 2. Entry points (draft card surface)

Every draft card exposes three image slots:
- `cover` — hero image on the card and on published output.
- `social` — 1:1 or 1.91:1 image used for OG/Twitter cards.
- `inline` — optional in‑body images.

**Card actions.**
- Primary CTA: **Generate Image** → opens sheet in `concepts` state, immediately POSTs `generate-image-concepts` (spinner + skeleton).
- Split dropdown **▾** with three fast‑paths:
  1. **AI Concepts** (default) — brainstorm 3 visual directions from draft copy.
  2. **Illustration (direct)** — skip concepts, use the specialized illustration prompt.
  3. **Infographic (data‑driven)** — extract stats; short‑circuit with a "no data" hint when the draft has none.

**Existing images.** Thumbnails render on the card, grouped by `image_type`. Tapping a thumb opens a detail view; a trailing `+` tile re‑opens the sheet in `concepts` state for another concept at the same slot.

## 3. State machine (modal)

```text
      ┌─────────┐  concepts loaded / pick concept
      │concepts │───────────────────────────────┐
      └────┬────┘                               │
           │ user picks concept or types custom │
           ▼                                    │
      ┌─────────┐  SSE partial frames (blur)    │
      │generate │◀──────────────────────────────┘
      └────┬────┘
           │ image_generation.completed
           ▼
      ┌─────────┐
      │ result  │──▶ regenerate ──▶ generate
      └────┬────┘
           │ (optional)
           ├─▶ crop
           ├─▶ text-overlay
           │
           ▼
        SAVE  ──▶ upload → generated_images → draft_images → mirror → close
```

**Per‑state contract.**

| State | Inputs | Outputs | Exit |
|---|---|---|---|
| `concepts` | `draftId`, `role`, style template, aspect | `Concept[]` | pick concept → `generate` |
| `generate` | `prompt`, `aspect`, `style` | streamed partial PNG (base64) | `.completed` event → `result` |
| `result` | final PNG data URL, prompt, concept | user decision | save / regenerate / crop / overlay |
| `crop` | image bytes, target aspect | cropped bytes | back to `result` |
| `text-overlay` | image bytes, overlay spec | composited bytes | back to `result` |
| `save` | bytes/URL, `role`, `draftId`, `prompt` | attached row | close sheet, invalidate queries |

Failure at any step surfaces a toast and returns to the previous state; the sheet never traps the user.

## 4. Data model (migration‑ready SQL)

Three tables. Every `CREATE TABLE` in `public` is followed by `GRANT` + `ENABLE RLS` + policies. Policies scope to `auth.uid()`.

```sql
-- ---------------------------------------------------------------
-- 4.1 Style catalog (server-driven grid, admin-managed)
-- ---------------------------------------------------------------
CREATE TABLE public.image_generation_styles (
  id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  style_id        TEXT UNIQUE NOT NULL,           -- stable key, e.g. 'editorial_photo'
  label           TEXT NOT NULL,
  category        TEXT NOT NULL,                  -- 'photography'|'artistic'|'3d'|'editorial'|'infographic'
  brand_feel      TEXT,
  thumbnail_url   TEXT,
  reference_image_url TEXT,
  style_prompt    TEXT NOT NULL,                  -- injected as [STYLE_TEMPLATE]
  supported_types TEXT[] NOT NULL DEFAULT ARRAY['cover','social','inline'],
  display_order   INT  NOT NULL DEFAULT 0,
  is_enabled      BOOLEAN NOT NULL DEFAULT true,
  created_at      TIMESTAMPTZ NOT NULL DEFAULT now(),
  updated_at      TIMESTAMPTZ NOT NULL DEFAULT now()
);
GRANT SELECT ON public.image_generation_styles TO authenticated, anon;
GRANT ALL    ON public.image_generation_styles TO service_role;
ALTER TABLE public.image_generation_styles ENABLE ROW LEVEL SECURITY;

CREATE POLICY "styles readable by anyone signed in or anon"
  ON public.image_generation_styles FOR SELECT
  USING (is_enabled = true);

CREATE POLICY "styles writable by admins"
  ON public.image_generation_styles FOR ALL
  USING (public.has_role(auth.uid(), 'admin'))
  WITH CHECK (public.has_role(auth.uid(), 'admin'));

-- ---------------------------------------------------------------
-- 4.2 Media Hub / DAM row (reusable across drafts)
-- ---------------------------------------------------------------
CREATE TABLE public.generated_images (
  id             UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id        UUID NOT NULL REFERENCES auth.users(id) ON DELETE CASCADE,
  url            TEXT NOT NULL,                    -- signed URL or public CDN URL
  storage_path   TEXT,                             -- e.g. draft-media/<uid>/<ts>-<name>.png
  prompt         TEXT,
  style_id       TEXT REFERENCES public.image_generation_styles(style_id),
  aspect_ratio   TEXT,                             -- '16:9' | '1:1' | '4:5' | '9:16' | ...
  model          TEXT,                             -- 'google/gemini-3-pro-image' | 'openai/gpt-image-2'
  generated_by   TEXT NOT NULL,                    -- 'gemini' | 'gpt-image-2' | 'upload' | 'library'
  parent_image_id UUID REFERENCES public.generated_images(id) ON DELETE SET NULL,
  width          INT,
  height         INT,
  created_at     TIMESTAMPTZ NOT NULL DEFAULT now()
);
GRANT SELECT, INSERT, UPDATE, DELETE ON public.generated_images TO authenticated;
GRANT ALL ON public.generated_images TO service_role;
ALTER TABLE public.generated_images ENABLE ROW LEVEL SECURITY;

CREATE POLICY "owner rw" ON public.generated_images
  FOR ALL USING (auth.uid() = user_id) WITH CHECK (auth.uid() = user_id);

-- ---------------------------------------------------------------
-- 4.3 Polymorphic association: draft → image(s)
-- ---------------------------------------------------------------
CREATE TABLE public.draft_images (
  id                  UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id             UUID NOT NULL REFERENCES auth.users(id) ON DELETE CASCADE,
  draft_id            UUID NOT NULL,
  draft_source        TEXT NOT NULL,               -- 'content' | 'email_sequence' | 'press_release' | ...
  image_type          TEXT NOT NULL CHECK (image_type IN ('cover','social','inline')),
  image_url           TEXT NOT NULL,
  image_prompt        TEXT,
  generated_image_id  UUID REFERENCES public.generated_images(id) ON DELETE SET NULL,
  display_order       INT NOT NULL DEFAULT 0,
  created_at          TIMESTAMPTZ NOT NULL DEFAULT now()
);
GRANT SELECT, INSERT, UPDATE, DELETE ON public.draft_images TO authenticated;
GRANT ALL ON public.draft_images TO service_role;
ALTER TABLE public.draft_images ENABLE ROW LEVEL SECURITY;

CREATE POLICY "owner rw" ON public.draft_images
  FOR ALL USING (auth.uid() = user_id) WITH CHECK (auth.uid() = user_id);

CREATE INDEX draft_images_lookup
  ON public.draft_images (draft_source, draft_id, image_type, display_order);
```

**Storage.** Private bucket `draft-media`. Path convention `draft-media/<uid>/<timestamp>-<slug>.png`. Attach via long‑lived signed URLs (1 year); refresh via server function when they approach expiry.

**Why `draft_source` (polymorphic).** One image subsystem for every draft table (`content`, `email_sequence`, `press_release`, `social_post`, …). No `FOREIGN KEY` on `draft_id` — the reference is (`draft_source`, `draft_id`). New draft types require zero migrations to gain images.

## 5. Backend contracts (4 endpoints)

Split by transport:
- **`generate-image` is a streaming server route** (raw `Response`, SSE passthrough). Not a `createServerFn`, which cannot stream.
- The other three are ordinary typed server functions.

### 5.1 `generate-image-concepts` — server function

```ts
// input
{ draftId: string; role: 'cover'|'social'|'inline'; style?: string;
  aspectHint?: string; userDirection?: string; includeOverlayText?: boolean }

// output
{ concepts: Array<{
    prompt: string;         // ≤60‑word visual description
    style: string;          // style_id from image_generation_styles
    aspect: string;         // '16:9' | '1:1' | '4:5' | '9:16'
    palette: [string,string,string];   // 3 hex colors
    composition: string;    // 1 sentence
    rationale: string;      // 1 sentence, grounded in draft copy
    overlayText?: string;   // present only if includeOverlayText
  }>
}
```

Grounds on the draft's title + sections. Never fabricates statistics, brands, people.

### 5.2 `generate-illustration-prompt` — server function

```ts
// input
{ draftId: string }

// output
{ prompt: string; coreEmotion: string; centralElement: string;
  palette: string[]; style: 'illustration' }
```

Single specialized prompt — one central metaphor, no photorealism.

### 5.3 `generate-infographic-prompt` — server function

```ts
// input
{ draftId: string }

// output — success
{ hasData: true;
  prompt: string;
  hero: { headline: string; kpi?: { label: string; value: string } };
  blocks: Array<{ kind: 'stat'|'quote'|'timeline'|'compare'; payload: unknown }>;
  relationshipMap?: Array<{ from: string; to: string; label?: string }>;
  metadata: { source: string; asOf?: string };
}

// output — short-circuit
{ hasData: false; reason: string }
```

Extracts stats and relationships. If the draft has none, returns `hasData:false` so the client can gracefully offer Illustration or Concepts instead.

### 5.4 `generate-image` — **streaming server route**

Path: `POST /api/drafts/generate-image`
Body: `{ prompt: string; aspect?: string; style?: string; negativePrompt?: string; useHighQuality?: boolean }`

**Injection contract for every render (server‑side):**
```
[STYLE_TEMPLATE(style_id)] + [ASPECT(aspect)] + [CONCEPT_PROMPT(prompt)] + [NEGATIVE(negativePrompt)]
```

Route responsibilities:
1. Auth: bearer → `auth.uid()`; 401 if missing.
2. Credits: if the caller is not admin, `deduct_credit(1)`; 402 if empty.
3. Build the request body **for the chosen model's body shape** (see §6).
4. POST to `https://ai.gateway.lovable.dev/v1/images/generations` with `stream: true`.
5. **Pass `upstream.body` through unchanged** with `Content-Type: text/event-stream`. Do not wrap in a hand‑rolled `ReadableStream`; that buffers and kills partial previews on some runtimes.
6. On failure event, forward as SSE `error` frame so the client parser can surface it.

Client contract (SSE events):
- `image_generation.partial_image` — `{ b64_json, partial_image_index }`. Render as `data:image/png;base64,${b64_json}` **blurred**.
- `image_generation.completed` — `{ b64_json, usage }`. Final frame. **Remove blur.**
- `error` — `{ error: { message, code? } }`. Terminal. Surface message; do not wait for `completed`.

## 6. Model routing & the body‑shape gotcha

**Default:** `google/gemini-3-pro-image` (Gemini chat‑image body shape).
**Fallback:** `openai/gpt-image-2` (OpenAI images body shape).
**Always:** `stream: true`.

**Body shapes are not interchangeable — swapping only `model` breaks generation silently.**

```jsonc
// Gemini default
{
  "model": "google/gemini-3-pro-image",
  "messages": [{ "role": "user", "content": "<final prompt>" }],
  "modalities": ["image", "text"],
  "stream": true
}

// OpenAI fallback
{
  "model": "openai/gpt-image-2",
  "prompt": "<final prompt>",
  "size": "1024x1024",
  "quality": "low",
  "n": 1,
  "stream": true,
  "partial_images": 2
}
```

Rewrite the whole body when switching. OpenAI has `partial_images`/`quality`; Gemini ignores them (or worse, returns a chat completion describing the image with no `data[]`). The gateway normalizes the *response* to the OpenAI SSE shape, so the client parser stays identical.

**Client parser rules (mandatory):**
1. Use `eventsource-parser` (npm, ~4KB).
2. Wrap each `setState` in `flushSync(...)` — React 18 batches sibling `setState`s and coalesces partial frames into a single render, making the stream look non‑streaming.
3. Render partials with `filter: blur(16px)`; drop the blur on `image_generation.completed`.
4. Loop `reader.read()` until `done:true`; do not stop early on heuristics.
5. Treat missing `image_generation.completed` as failure.

Do not name providers in user‑facing copy. Say "AI" or "AI‑powered".

## 7. Save / attach flow (numbered + rollback)

Client → server ordering when the user taps **Attach to draft**:

1. **Reject `data:` URLs.** If the working image is a base64 data URL (from streaming), upload the bytes to `draft-media/<uid>/<ts>-<slug>.png` first; obtain a signed URL (1 year).
2. **Insert into `generated_images`** with `url`, `storage_path`, `prompt`, `style_id`, `aspect_ratio`, `model`, `generated_by`. Capture `savedImage.id`.
3. **Compute `display_order`.** `SELECT COALESCE(MAX(display_order), -1) + 1 FROM draft_images WHERE draft_id = $1 AND draft_source = $2 AND image_type = $3`.
4. **Insert `draft_images`** with `image_url = savedImage.url`, `generated_image_id = savedImage.id`, `image_prompt`, `display_order`.
5. **Mirror on parent** (fast list rendering). If `draft_source = 'content'` (or your primary draft table), `UPDATE` its `cover_image_url` or `social_image_url` column to the new URL.
6. **Emit `onImageSaved(url, prompt)`** → invalidate React Query keys `['draft-images', draftId]`, `['draft', draftId]`, `['drafts']` → close the sheet.

**Rollback rules.**
- Step 4 fails → `DELETE` the row created in step 2 to avoid orphan DAM entries.
- Step 5 fails → **do not** roll back steps 2–4. The image is attached; mirror is a cache. Log + toast.
- Step 1 fails → nothing to roll back; surface upload error.

## 9. LLM system prompts (verbatim)

### 9.1 Concepts

```
You generate visual concepts for a draft. Return exactly 3 concepts as JSON.

Grounding rules:
- Ground every visual claim in the draft's title and sections provided in [DRAFT].
- Never invent statistics, brand names, real people, or dates that are not in [DRAFT].
- Never describe copyrighted characters or real identifiable public figures.

Each concept must include:
- prompt: a ≤60‑word visual description, no camera brand names.
- style: one of the provided style_ids in [STYLES].
- aspect: one of ["16:9","1:1","4:5","9:16"], chosen to fit [ROLE].
- palette: exactly 3 hex colors that fit the concept.
- composition: one sentence.
- rationale: one sentence tying the concept to a specific line in [DRAFT].

Return: {"concepts":[…3…]}. No prose.
```

### 9.2 Illustration

```
You are an illustration director. Distill the draft into ONE central metaphor.

Return JSON:
{
  "prompt": "a single, concrete illustration prompt (no photorealism)",
  "coreEmotion": "one word",
  "centralElement": "one noun phrase, the metaphor's subject",
  "palette": ["#hex","#hex","#hex","#hex"]
}

Rules:
- No cameras, lenses, or photographic vocabulary.
- No real people, no logos, no copyrighted characters.
- Prefer symbolic composition over literal depiction.
```

### 9.3 Infographic

```
You extract data structure from a draft. If the draft contains no
statistics, numeric comparisons, timelines, or clear relationships,
return {"hasData": false, "reason": "<short reason>"} and STOP.

Otherwise return the NotebookLM‑style schema:
{
  "hasData": true,
  "hero": { "headline": "<≤10 words>", "kpi": { "label": "...", "value": "..." } },
  "blocks": [ { "kind": "stat|quote|timeline|compare", "payload": { ... } } ],
  "relationshipMap": [ { "from": "...", "to": "...", "label": "..." } ],
  "metadata": { "source": "draft", "asOf": "YYYY-MM-DD" },
  "prompt": "final render prompt for an infographic image, referring only to data present above"
}

Never invent numbers. Every stat must be quotable from the draft verbatim.
```

## 10. Credits, auth, RLS

- **Auth.** Every server function uses the auth middleware (`requireSupabaseAuth` equivalent) that puts an authenticated Supabase client + `userId` on context. Public routes may not call these functions in loaders.
- **Credits.** `generate-image` deducts 1 credit per successful stream **start**. Skip deduction for users with `has_role(auth.uid(), 'admin')`. Return HTTP `402` with `{ error: 'INSUFFICIENT_CREDITS' }` when empty; the client surfaces a toast pointing to billing.
- **RLS.** Every table policy scopes to `auth.uid() = user_id`. Style catalog is world‑readable when `is_enabled = true`; writes require admin role.
- **Storage.** `draft-media` is private. Never emit raw storage keys to the client; only signed URLs.

## 11. Mobile behavior (structural spec, no styling)

- `<640px`: sheet slides up from the bottom, `max-height: 92vh`, rounded top corners, drag handle optional. Backdrop dismisses on tap.
- Style grid: 2‑column horizontally scrolling strip when `<640px`; snap points on cards.
- Concept cards: stack vertically, full‑width, tap target ≥44pt.
- Preview: fills `90vh`; **sticky bottom action bar** with `Regenerate` (secondary) + `Save` (primary) inside the thumb zone.
- Streaming partial: rendered with a blur; blur removed on `image_generation.completed`.
- Loader states: never a full‑screen spinner — always a skeleton in the state's actual layout so the user sees progress in place.
- Errors: inline in the sheet, never a route change; retry stays one tap away.

## 12. Acceptance checklist (Given / When / Then)

- **Concepts grounded.** Given a draft with title "Q3 launch retro" and sections about shipping delays, when I open the sheet, then the 3 returned concepts each cite a phrase from the draft in `rationale` and none mention numbers or brands not present in the draft.
- **Streaming visible.** Given I picked a concept, when the model starts rendering, then I see at least 1 blurred partial frame before the final image, and the final frame is not blurred.
- **flushSync respected.** Given multiple SSE events arrive in one chunk, when the client parses them, then every partial triggers its own React render (verified by a render counter in dev).
- **Model switch safety.** Given the fallback is engaged, when the request body is built, then it uses the OpenAI shape (`prompt`, `size`, `partial_images`) and does **not** contain `messages` or `modalities`.
- **Save monotonicity.** Given a card already has 2 `cover` images with `display_order` 0 and 1, when I attach a new cover, then a new `draft_images` row is written with `display_order = 2` and a new `generated_images` row exists linked by `generated_image_id`.
- **Mirror updates.** Given `draft_source = 'content'`, when I save a `cover`, then the parent row's `cover_image_url` equals the new signed URL within the same request.
- **RLS enforcement.** Given user A owns a draft, when user B queries `draft_images` for that draft, then 0 rows return.
- **Credit exhaustion.** Given the user has 0 credits and is not admin, when they trigger `generate-image`, then the response is 402 and the sheet shows a "You're out of credits" toast with a link to billing.
- **Mobile layout.** Given viewport `375×812`, when the sheet opens, then it is anchored to the bottom, max‑height 92vh, sticky action bar visible without scrolling.
- **No orphaned DAM row.** Given step 4 (`draft_images` insert) fails, when the save flow ends, then the corresponding `generated_images` row created in step 2 has been deleted.
- **Streaming failure is terminal.** Given the model emits an `error` SSE frame, when the client receives it, then the sheet stops the spinner immediately and surfaces `error.message` without waiting for `image_generation.completed`.
