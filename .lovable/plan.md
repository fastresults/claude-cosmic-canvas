# Draft Image Generation — Portable Lovable Prompt

## Goal
Produce a single markdown deliverable at `docs/prd/draft-image-generation-lovable-prompt.md` that another Lovable project can paste as a prompt to reproduce this app's Draft → Generate Image → Save-to-Card workflow. The doc is architecture + contracts + prompts only — zero visual styling opinions beyond mobile structural rules (bottom sheet, thumb-zone, sticky action bar).

## Scope
- No code changes to this app. Only a new markdown file.
- Grounded in the shipped implementation here (`ImageAssociationSheet`, `streamDraftImage`, `/api/drafts/generate-image`, `create_media`, `create_drafts`, `useDraftImages`, `attachDraftImage`) so the exported contract matches what actually works.
- Adapted for AI-first, mobile-first target apps (Gemini 3 Pro Image default, streaming partials with blur, bottom-sheet modal).

## Deliverable Structure
Single file, ~10 sections:

1. **Overview & user story** — one screen: "As a creator, from any draft card I can attach cover/social/inline images generated by AI, uploaded, or reused from library, in ≤3 taps."
2. **Entry points** — Draft card slots (`cover` | `social` | `inline`), primary CTA + dropdown (AI Concepts / Illustration / Infographic), existing thumbs + "+" tile re-opens sheet.
3. **State machine** — `concepts → generate (streamed) → result → (crop | overlay) → save`. Documented as a diagram + per-state inputs/outputs/exit conditions.
4. **Data model (SQL, migration-ready)** — three tables:
   - `image_generation_styles` (server-driven style grid, `supported_types[]`, `display_order`, `is_enabled`, admin-only CRUD via `has_role('admin')`).
   - `draft_images` polymorphic association (`draft_id`, `draft_source`, `image_type`, `display_order`, `image_prompt`, `generated_image_id`).
   - `generated_images` (Media Hub / DAM row for reuse).
   - Every `CREATE TABLE` followed by `GRANT` + `ENABLE RLS` + policies scoped to `auth.uid()`.
5. **Backend contracts (4 endpoints)** — full JSON I/O, no implementation:
   - `generate-image-concepts` → 3 concepts (`prompt`, `palette[3]`, `composition`, optional `overlayText`).
   - `generate-illustration-prompt` → `{prompt, coreEmotion, centralElement, palette[]}`.
   - `generate-infographic-prompt` → NotebookLM schema or `{hasData:false}` short-circuit.
   - `generate-image` → **streaming SSE** (`image_generation.partial_image` / `.completed` / `error`), returns final `imageUrl` after storage upload.
   - Injection contract for every render: `[STYLE_TEMPLATE] + [ASPECT] + [CONCEPT_PROMPT] + [NEGATIVE_PROMPT]`.
6. **Model routing** — Default `google/gemini-3-pro-image` (Gemini chat-image body shape), fallback `openai/gpt-image-2`. Always `stream: true`. Client parser uses `eventsource-parser` + `flushSync` (mandatory) + blur-until-final. Note the body-shape switch rule when swapping providers.
7. **Save/attach flow (numbered, with rollback)**:
   1. Reject `data:` URLs — upload to storage first (`draft-media/<uid>/<ts>-<name>`), get signed URL (1yr).
   2. Insert `generated_images` row → capture `id`.
   3. `SELECT max(display_order)` for `(draft_id, draft_source, image_type)`.
   4. Insert `draft_images` with `display_order = max + 1`.
   5. If `draft_source='content'` (or equivalent primary draft table), mirror `cover_image_url` / `social_image_url` on parent for list rendering.
   6. Emit `onImageSaved(url, prompt)` → invalidate `['draft-images', draftId]`, `['draft', draftId]`, `['drafts']` → close sheet.
   - Rollback: on step 4 failure, delete row from step 2; on step 5 failure, keep image (attach succeeded) but surface toast.
8. **Style seed data** — ~15 rows covering Photography & Realism, Artistic & Painterly, 3D & Dimensional, Editorial, Infographic. Each with `style_prompt`, `supported_types`, `display_order`.
9. **Prompt system messages (verbatim)** — the three LLM system prompts used for Concepts / Illustration / Infographic, with instructions on grounding to draft copy and forbidding fabricated stats.
10. **Credits, auth, RLS** — 1 credit per `generate-image`, skipped for admins via `has_role`; bearer token → `auth.uid()` → RPC deduct → 402 on empty; every table policy scopes to `auth.uid() = user_id`.
11. **Mobile behavior (spec, not styling)** — `<640px` renders as bottom sheet (max-h 92vh, rounded top, drag handle optional), style grid becomes 2-col horizontal scroll strip, concept cards stack vertically, preview fills 90vh with sticky bottom action bar (Regenerate | Save), primary CTAs sit in the bottom thumb-zone.
12. **Acceptance checklist (Given/When/Then)** — covers: concepts return 3 items grounded in draft copy; streaming shows blurred partials that sharpen on completion; save creates both `generated_images` and `draft_images` rows with monotonic `display_order`; parent mirror columns update for `content` drafts; 402 surfaces credit-exhausted toast; RLS blocks cross-user reads; bottom-sheet layout activates <640px.

## Technical Notes for the Prompt Author
- Reference this repo's working artifacts as the "source of truth" section at the top so the target Lovable agent can mirror them: `ImageAssociationSheet.tsx`, `streamImage.ts`, `routes/api/drafts/generate-image.ts`, `hooks/useDraftImages.ts`, `lib/drafts/drafts.functions.ts`.
- Include the Gemini vs OpenAI body-shape gotcha inline (do not just swap `model`).
- Include the `flushSync` rule and blur-until-`completed` rule inline — omitting either is the #1 failure mode.
- Include the "polymorphic `draft_source`" rationale so target apps with multiple draft tables (email, PR, blog) reuse one image subsystem.
